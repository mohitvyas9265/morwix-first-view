Morwix

A school-to-home communication platform — replacing lost paper circulars and noisy WhatsApp groups with a school-owned app that actually knows who read the notice.

v0.4 7 Aug 2026 Owner: Mohit Vyas ● Draft

01 The short version

Here's the whole idea in one breath, before we get into the weeds.

The problem

  • Schools send notices on paper (lost in school bags, no proof anyone saw it) or WhatsApp (noisy, no targeting, personal numbers everywhere).
  • Collecting consents and RSVPs means chasing paper slips by hand.
  • There's no school-owned channel with targeting, read tracking, and responses.

The solution

  • An app-first channel schools own — send a notice, and see who got it and who read it.
  • Grows in three stages: broadcast → wider audience → actionable (consents, RSVPs, forms).
  • Puts an app in every parent's pocket — the base everything else builds on.
✓ Goals
  • Ship the simplest sellable MVP: one-way circulars to parents with read tracking.
  • Prove value in 1–2 pilot schools, then earn each next stage.
  • Build the multi-tenant, push-enabled foundation every stage reuses.
– Not now
  • Attendance — deferred (revisit later as the daily-habit lever).
  • Payments, e-signature, document upload.
  • Self-serve web admin — early onboarding is concierge (we do it).
  • Colleges / universities — K-12 first.

02 The roadmap, in three stages

Each stage stands on its own and is sellable. We only commit to Stage 1 now — the rest we earn. Tap a stage to see what's in it.

Stage 1 · MVP

One-way circulars to parents

Broadcast a notice to a targeted set of parents, delivered by push and an in-app inbox, with read tracking. The simplest thing that's genuinely better than paper or WhatsApp.

  • Targeting: whole school, a class, a group, or specific parents — recipient list snapshotted at send time.
  • Delivery: push (APNs/FCM) + in-app inbox; marked read on open.
  • Tracking: delivered & read counts, and who hasn't read yet.
Stage 2

Circulars to parents and students

Widen the audience so notices can reach students directly, not just parents. Targeting becomes role-aware.

  • Role-based targeting: parents, students, or both — within any audience.
  • Same experience (push + inbox) for student recipients; tracking reported by role.
  • Open question: do students get their own logins, or view via a linked parent? Minor-account age & consent decide this.
Stage 3

Actionable circulars

The differentiator paper can't match: collect structured responses with live tracking and reminders.

  • Actions: acknowledge, consent (approve/decline), RSVP/choice, and simple forms — with an optional deadline.
  • Responses: one tap, idempotent, editable until the deadline, then locked.
  • Tracking: tallies by answer, a non-responder list, and reminders that re-notify only them.

05 Features, in detail

Click to expand. Each carries its own acceptance criteria so there's nothing to guess when we build.

Stage 1 One-way circulars to parents ›

An admin (optionally a teacher) composes a circular, targets parents, and sends via push + inbox. Broadcast only — no responses yet.

Functional

  • Audience targeting; recipient set snapshotted at send.
  • Push (APNs/FCM) + in-app inbox; read-on-open.
  • Optional attachment (image/PDF of the notice).
  • Delivered & read counts + who-hasn't-read list.

Acceptance

  • Reaches only the targeted parents (verified).
  • Push <60s (online); appears in inbox.
  • Read status updates on open; counts reflect it.
  • All data tenant-scoped (isolation tested).
Stage 2 Circulars to parents and students ›

Extend the audience so notices can reach students directly. Targeting becomes role-aware.

  • Choose recipient roles — parents, students, or both — within any audience.
  • Students get the same push + inbox; tracking reported per role.
  • Resolve first: student logins vs. view-via-parent, plus minimum age & consent capture.
Stage 3 Actionable circulars ›

Collect structured responses — the thing WhatsApp and paper can't do well.

Functional

  • Actions: acknowledge, consent (approve/decline), RSVP/choice, simple forms.
  • One-tap, idempotent, editable until deadline, then locked.
  • Tally by answer, non-responder list, targeted reminders.

Acceptance

  • A response records exactly once and shows in tracking.
  • Non-responder list accurate; reminder hits only them.
  • Responses lock after the deadline.
Foundation Auth, tenancy, roster & notifications ›
  • Auth: managed provider (Cognito / Auth0), not custom. Roles: admin, teacher, parent, student; parent↔student links.
  • Tenancy: every record scoped by tenant; isolation enforced centrally. Concierge roster import early.
  • Notification service: the shared spine — Expo → APNs/FCM, device-token registry, per-category mute, delivery logging.

08 The non-negotiables

Quality bars that don't show up as features but decide whether schools trust us.

🔒 Privacy & security

Minors' PII: encryption in transit & at rest, RBAC, correct audience targeting, audit logs, and a consent model. Comply with DPDP / FERPA-COPPA by market. A privacy review is required before real data.

🏢 Multi-tenancy

Shared DB with a tenant_id, scoping enforced centrally — never per-query. Path to an isolated DB for large tenants later.

🔔 Push

APNs + FCM via Expo, under 60s, with graceful fallback to the in-app inbox if push is off.

📶 Connectivity

Online-first throughout — circulars don't require offline support (that bar returns if attendance does).

📱 App versioning

Backward-compatible API + a force-update check; ship JS-only updates over-the-air via EAS Update.

🌍 Reach

Usable on low-end Android; internationalization-ready; legible, large touch targets.

09 What could go wrong

And how we plan to blunt each one. Severity is a quick read, not a science.

▲ High
Retention / frequency. One-way circulars are episodic and attendance (the daily habit) is deferred. → Win by being the school's default channel and adding Stage 3 interactivity; keep attendance as the eventual retention lever.
▲ High
Mis-targeted circular → privacy incident. → Snapshot recipients, show an audience preview before send, and run isolation tests.
◆ Med
Thin Stage-1 vs WhatsApp. → Lead on what WhatsApp can't do: targeting, read tracking, school-owned data, no personal-number sharing.
◆ Med
Admin adoption. → Concierge setup, import existing groups, make the tracking value obvious on day one.
◆ Med
Minor-PII compliance (heightened once students get accounts). → Privacy-by-design, consent, audit logs, retention policy.
▲ High
Small-team scope creep. → Commit only Stage 1; earn each next stage. App-store latency → set up store accounts early, use OTA for JS.
